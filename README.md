# Video Analytics

An MVP CLI for local video analysis. It accepts a local video file, creates an audio transcript, sends the video or preview to Qwen through OpenRouter for visual analysis, fetches YouTube metadata and analytics, and stores all artifacts under `outputs/` and `.system/`.

## Quick Start

```bash
cp .env.example .env
npm test
npm run analyze -- --video ./fixtures/sample.mp4 --youtube-id VIDEO_ID
```

Real visual analysis requires `OPENROUTER_API_KEY`. Local transcription requires `ffmpeg`, `ffprobe`, `whisper-cli`, and a local model path in `VIDEO_ANALYTICS_WHISPER_MODEL`. To use OpenRouter speech-to-text instead of local Whisper, set `VIDEO_ANALYTICS_TRANSCRIBER=openrouter-stt`.

The YouTube Data API requires `YOUTUBE_API_KEY`. YouTube Analytics uses OAuth:

```bash
npm run youtube:auth
```

If keys are not configured, the CLI does not fail. It writes JSON with `skipped_*` statuses for unavailable sections.

Secrets should live only in `.env` and `.system/youtube-oauth-token.json`. These files are ignored by Git and must never be committed to a public repository.

Important: visual analysis uploads the source video or a compressed preview to OpenRouter/Qwen. Do not use that mode for sensitive videos unless you have permission from the data owner. For private/local-only runs, leave `OPENROUTER_API_KEY` empty: transcript and YouTube JSON artifacts can still be created, while visual analysis will be marked as `skipped_missing_openrouter_key`.

## Inputs

Single video:

```bash
npm run analyze -- --video "/path/to/video.mp4" --youtube-url "https://youtu.be/VIDEO_ID"
```

Batch manifest:

```bash
cp inputs/videos.example.jsonl inputs/videos.jsonl
npm run analyze -- --input inputs/videos.jsonl
```

`inputs/videos.jsonl` is a local ignored manifest. Use `inputs/videos.example.jsonl` as a sanitized template:

```jsonl
{"video_path":"/path/to/video.mp4","youtube_url":"https://youtu.be/VIDEO_ID","title":"03 - Daily Planning"}
{"video_path":"/path/to/video2.mov","youtube_id":"VIDEO_ID_2"}
```

## Outputs

For each video, the CLI creates:

```text
outputs/<safe-video-stem>/
  ТРАНСКРИПТ_<stem>.md
  ВИЗУАЛЬНЫЙ_СЦЕНАРИЙ_<stem>.md
  YOUTUBE_<youtube_id>.json
  RUN_<run_id>.json
.system/<run_id>/
  fingerprint.json
  ffprobe.json
  audio.wav
  transcript.raw.json
  qwen.request.json
  qwen.response.json
  youtube.video.json
  youtube.channel.json
  youtube.latest-uploads.json
  youtube.comments.json
  youtube.captions.json
  youtube.analytics-summary.json
  youtube.analytics-daily.json
  youtube.analytics-retention.json
  youtube.analytics-traffic-sources.json
  youtube.analytics-traffic-details.json
  youtube.analytics-subscribed-status.json
  youtube.analytics-geography.json
  youtube.analytics-devices.json
  youtube.analytics-demographics.json
  youtube.analytics-engagement.json
  youtube.channel-benchmark.json
  youtube.data-api.json
  youtube.analytics-api.json
```

`outputs/` and `.system/` are local working artifacts and are not committed by default.

The final publication report is not generated by a separate CLI command. An agent should read the transcript, visual scenario, `YOUTUBE_<id>.json`, and `RUN_<run_id>.json`, then create the report according to `SKILL.md`.

Report filename rule: the video title must be the final part of the filename. Example:

```text
outputs/reports/YOUTUBE_REPORT_<id>_<safe-video-title>.md
```

If there is no YouTube ID, use:

```text
outputs/reports/YOUTUBE_REPORT_<safe-video-title>.md
```
